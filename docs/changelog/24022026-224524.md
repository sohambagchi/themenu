[feat] add deterministic walmart receipt parsing with staging conversion rules

## Completed
- Replaced `src/lib/staging.ts` with a deterministic Walmart receipt parser that:
  - Parses item blocks from `Shopped|Weight-adjusted|Unavailable Qty N` patterns.
  - Extracts token keys and deterministic token hashes for conversion matching.
  - Computes effective quantity as `line qty * embedded pack/count` (with rule override support).
  - Marks rows as `resolved`, `needs_review`, or `ignored`.
- Extended shared types in `src/lib/types.ts` for richer staging state and sourcing conversion rule models.
- Added `GET/POST /api/sourcing/conversions` in `src/app/api/sourcing/conversions/route.ts` for deterministic conversion rule lookup/upsert with validation, origin checks, and auth.
- Added `src/lib/sourcingApi.ts` for browser-side conversion rule fetch/upsert wrappers.
- Updated `src/components/staging-panel.tsx` to:
  - Load conversion rules via React Query.
  - Re-parse with rules into `Resolved / Needs Review / Ignored` sections.
  - Commit only resolved rows to Pantry.
  - Allow `Confirm Mapping` from review rows to upsert conversion rules.
- Added DB support in `supabase/schema.sql` and migration `supabase/migrations/20260225_sourcing_conversion_rules.sql` for `public.sourcing_conversion_rules` and related indexes/policies/trigger.

## ADR
- Persist confirmed conversion mappings in a global deterministic hash-table (`source + token_hash`) instead of per-user storage.
- Treat `items.quantity` as effective units for sourcing receipts (line quantity multiplied by embedded pack/count metadata).
- Keep parser deterministic and staging-first: unmatched rows are `needs_review`, unavailable rows are `ignored`, and only resolved rows are committable.
