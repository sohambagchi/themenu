[feat] migrate walmart pdf parsing to js and add unit-aware quantities

## Completed
- Replaced shell-based PDF extraction with a JS-only Walmart PDF parser in `src/lib/walmartPdf.ts` that decodes embedded PDF text streams and ToUnicode CMaps.
- Kept the Sourcing PDF API route (`POST /api/sourcing/pdf-text`) and removed runtime dependence on `pdftotext` binaries.
- Updated `src/lib/staging.ts` parsing flow to handle both:
  - existing raw text format (`Shopped Qty N` on one line), and
  - JS-extracted PDF format where status and `Qty N` may arrive on separate lines.
- Added regression tests in `test/walmart-pdf-extract.test.ts` to verify JS extraction and downstream staging parsing from `test/walmart.pdf`.
- Added/propagated quantity unit support and fractional quantity handling across app/API/DB paths, including:
  - shared types (`quantityUnit`),
  - quantity parsing/formatting utilities,
  - Sourcing, Dashboard, and Mise en Place UI edits,
  - item validation and API route handling,
  - schema + migrations for `items.quantity_unit` and numeric quantity precision,
  - conversion rule support for canonical quantity units.
- Updated docs guides for codebase map, extensibility, and database details.
